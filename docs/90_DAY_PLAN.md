# ModelFit · Realistic 90-day execution plan

A proposed plan, dependent on access, capacity and accountable sponsors. No pilot or partnership is committed.

| Period | Work and owners | Exit evidence |
| --- | --- | --- |
| Days 1–30 | Product lead: interview service owners, evaluators and approvers; map authority and repeat work. Governance adviser: validate applicable rules, source/scope and exception eligibility. Evaluation lead: select permitted public data and expand bilingual cases. Analyst: measure baseline effort and evidence quality. | At least 8–12 interviews if access permits; two mapped workflows; sourced requirement catalogue with validation status; permissioned dataset shortlist; baseline protocol and recorded timings; explicit go/no-go for pilot design. |
| Days 31–60 | Engineering: identity, access control, data retention, schema/migrations, evidence storage and audit integrity. Evaluation lead: connect a real provider if authorized, test grounding/refusal and multilingual quality with human reviewers. Security/accessibility reviewers: assess threat model, prompt injection, file handling, keyboard and assistive-technology use. | A permissioned pilot workflow; documented reviewer authority; expanded test set with limitations; independent review of critical gates; security findings triaged; accessibility issues prioritized; rollback and incident procedures. |
| Days 61–90 | Pilot owner: run a small controlled pilot with explicitly authorized participants. Analyst: measure effort, reuse correctness and missed/false change impacts. Operations owner: define evidence refresh, incident response, support, cost and review responsibilities. Sponsor: decide whether to stop, iterate or expand. | Paired baseline/pilot measurements; quality and safety review; user feedback; named operational owner; cost estimate based on actual usage; explicit rollout decision with unresolved risks and conditions. |

## Controls and dependencies

Identity, authority validation, data permission and trustworthy evaluation are prerequisites for organizational decisions. Keep deployment decisions with accountable humans. No automatic procurement, real service deployment, provider telemetry or legal policy automation should be implied until deliberately implemented and verified.

Prioritize the core context → evidence → decision → change loop. Defer federation and large-scale benchmark infrastructure until the pilot demonstrates a need. A pilot with unresolved critical security or evidence-quality defects should not proceed to operational use.
